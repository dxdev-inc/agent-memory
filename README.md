# agent-memory

A small command line tool for keeping a folder of agent memory files healthy. It checks that your always-loaded index fits inside the size limits agent tools load at session start, finds memory files nobody links to and links that point nowhere, recalls the right memory for a task hint, and flags near-duplicate memories so you can clean them up with a reviewed, fully reversible step. It uses only the Python standard library, never calls a model and never touches the network.

## Try it

You need Python 3.10 or newer and git.

```
git clone https://github.com/dxdev-inc/agent-memory.git
cd agent-memory
pip install -e .
agent-memory check --memory-dir examples/memory
```

That checks eight invented sample memories and reports one problem on purpose. The [full walkthrough](#quick-start-from-zero) below fixes it, finds a duplicate and undoes the change. Deeper reading: [the file format](#the-memory-file-format), [every command](#commands), [what `apply` does to your files](#commands).

## The memory file format

A memory folder is flat. Every topic file is `<slug>.md` with frontmatter, and two index files sit beside them.

```
memory/
  MEMORY.md                         short, curated, always loaded (keep under 200 lines / 25 KB)
  INDEX.md                          full catalog, generated by `agent-memory rebuild-index`
  feedback_run_tests_first.md       one topic per file
  user_prefers_short_replies.md
```

A topic file:

```markdown
---
name: feedback_run_tests_first
description: "One line that makes a reader want to open this file."
metadata:
  type: feedback        # user | feedback | project | reference
---

The rule or fact, in a sentence or two.

**Why:** the reason, so edge cases can be judged.

**How to apply:** when and where it kicks in. Link related memories with [[other_slug]].
```

`name` and `description` are required, because the description is what makes a memory findable. `[[slug]]` links match either a file's `name` or its filename without `.md`.

## Quick start from zero

You need Python 3.10 or newer and git.

```
git clone https://github.com/dxdev-inc/agent-memory.git
cd agent-memory
python -m venv .venv
```

Activate the environment. On Windows (PowerShell):

```
.venv\Scripts\Activate.ps1
```

On macOS or Linux:

```
source .venv/bin/activate
```

Install it with the test tools:

```
pip install -e .[dev]
```

(In zsh, quote the extra: `pip install -e ".[dev]"`.)

The repo ships a sample folder in `examples/memory`: eight invented memories, one deliberate near-duplicate pair and one link that points nowhere. Run the checker on it as it is:

```
agent-memory check --memory-dir examples/memory
```

```
MEMORY.md: 17 lines (target 180, hard 200) [ok]
MEMORY.md: 967 bytes (target 17408, hard 25600) [ok]
Topic files: 8
Body wikilinks: 1 unresolved [[..]] target(s) (informational): reference_branch_policy

FAIL: 1 problem(s):
  - INDEX.md missing. Run `agent-memory rebuild-index`.
```

It exits with code 1. The sample has no `INDEX.md` yet, and one memory links to `[[reference_branch_policy]]`, which does not exist. The tool will write files, so work on a copy:

macOS or Linux: `cp -r examples/memory demo-memory`
Windows (PowerShell): `Copy-Item -Recurse examples/memory demo-memory`

Build the index, then check again:

```
agent-memory rebuild-index --memory-dir demo-memory
agent-memory check --memory-dir demo-memory
```

```
Rebuilt INDEX.md: 8 entries, 1731 bytes
MEMORY.md: 17 lines (target 180, hard 200) [ok]
MEMORY.md: 967 bytes (target 17408, hard 25600) [ok]
Topic files: 8
INDEX.md references: 8 (orphans 0, dangling 0)
Body wikilinks: 1 unresolved [[..]] target(s) (informational): reference_branch_policy

OK: memory index healthy.
```

An unresolved `[[link]]` is reported but never fails the check. A broken link in `MEMORY.md` or `INDEX.md` does.

Ask for the memories that fit a task:

```
agent-memory recall "should I run the tests before telling the user it is fixed" --memory-dir demo-memory -n 2
```

```
  0.80  feedback_run_tests_before_saying_done  (0d old)
        Run the test suite and read the result before telling the user a change is done or fixed.
  0.42  feedback_test_before_declaring_done  (0d old)
        Run the tests and read the output before declaring a change done, fixed or working.
```

The ages show 0d because you just copied the files. Now look for duplicates. This only writes a proposal; no memory is changed:

```
agent-memory propose --memory-dir demo-memory --run-id demo
```

```
memory: 8 files in demo-memory
memory: 1 near-duplicate candidate pair(s) (lexical)
memory: proposal written to .agent-memory-runs/demo/proposal.md

  8 memories read, 1 proposal(s), 1 applicable
  review:  .agent-memory-runs/demo/proposal.md
  then:    agent-memory apply .agent-memory-runs/demo
```

Open `.agent-memory-runs/demo/proposal.md`. Every item ends with a `decision: hold` line. Change the one you agree with to `decision: apply` and save. To do that from the command line on any system:

```
python -c "import pathlib; p = pathlib.Path('.agent-memory-runs/demo/proposal.md'); p.write_text(p.read_text().replace('decision: hold', 'decision: apply'))"
```

Rehearse, then run it for real:

```
agent-memory apply .agent-memory-runs/demo
agent-memory apply .agent-memory-runs/demo --yes
```

```
apply: 1 to execute, 0 held, 0 rejected, 0 refused
WOULD retire  feedback_test_before_declaring_done
apply: dry run. Re-run with --yes to execute.
```

The second command prints the same first line, then the snapshot location, `RETIRED feedback_test_before_declaring_done.md -> demo/`, and the undo command. Absolute paths in that output are your own. The retired file now sits in `demo-memory/.retired/demo/`. Put everything back:

```
agent-memory apply .agent-memory-runs/demo --undo --yes
```

It prints `undo: restored 10 files into <your path>/demo-memory`, and every file is byte for byte what it was before.

To walk through it a second time, give `propose` a new run id (`--run-id demo2`, and use `.agent-memory-runs/demo2` in the later commands). It refuses to reuse `demo` once that run has been applied, so an old undo snapshot can never be mixed up with a new proposal.

## Commands

All commands that read a memory folder take `--memory-dir DIR`, or read the `AGENT_MEMORY_DIR` environment variable.

| Command | What it does |
|---|---|
| `agent-memory check` | Reports `MEMORY.md` size against the target (180 lines / 17 KB) and the hard cap (200 lines / 25 KB), names the entries that would be dropped past a cap, lists topic files missing from `INDEX.md`, links that point at missing files, and files without `name` or `description`. Exit 1 on any problem. |
| `agent-memory rebuild-index [--areas FILE]` | Regenerates `INDEX.md` from frontmatter, one line per memory. By default entries are grouped by `type`. `--areas` takes a JSON file such as `{"areas": {"Deploys": ["deploy", "release"]}}`: the first area whose keyword appears in a memory's name or filename wins, the rest go under Other. |
| `agent-memory recall "<hint>" [-n 5] [--sid ID] [--json]` | Local TF-IDF lookup over filename, name and description, with a smaller weight on the body. Returns a few hits or none. With `--sid`, a memory already shown for that session id is not shown again (the seen list lives in `<memory-dir>/.recall-seen/`). |
| `agent-memory propose [--runs-dir DIR] [--run-id ID]` | Finds near-duplicate pairs with a word-overlap index and writes `proposal.md` and `proposal.json` into `.agent-memory-runs/<run-id>/`. Changes no memory. A run id is letters, digits, `-` and `_`, with dots only inside the name (no slashes, no `..`, not empty). The runs folder must be outside the memory folder; `propose` and `apply` refuse otherwise. |
| `agent-memory apply RUN_DIR [--yes] [--undo]` | Executes the items you marked `decision: apply`. Dry run unless `--yes`. `--undo` restores the folder from the snapshot taken before the first change. |

How `apply` keeps you safe:

* Nothing runs without a human mark; every item starts as `hold`.
* Retired files move to `<memory-dir>/.retired/<run-id>/` with a `MANIFEST.json`. They are never deleted.
* A full snapshot of the folder is taken before the first change.
* A run applies once. Applying it again is refused, so its manifest is never overwritten; `--undo` still works.
* The dry run runs the same checks as `--yes`, including a merge whose target file already exists, and prints `WOULD REFUSE` for what the real run would refuse.
* `merge` items are supported when `proposal.json` carries `merged_slug` and `merged_body`, but `propose` does not write those. It proposes `retire` of the smaller file in a pair and keeps the larger. A retire loses whatever the dropped file said that the kept one does not, so read both first.

The duplicate finder works on words, not meaning. Two memories that say the same thing in different words are not found, and an empty result is not proof there are none.
